# Customer Churn Prediction App

A deployed machine learning app that predicts telecom customer churn, served via
FastAPI with a simple browser front end. Built on the [Telco Customer Churn
dataset](https://www.kaggle.com/datasets/blastchar/telco-customer-churn).

## Project structure

```
churn-app/
├── app/
│   ├── main.py          # FastAPI app, routes
│   ├── model_utils.py   # Model loading + prediction logic
│   └── schema.py         # Pydantic request/response schemas
├── frontend/
│   └── index.html        # Simple form UI, calls the /predict endpoint
├── model/
│   └── churn_model.joblib  # <-- put your trained model here (see below)
├── Dockerfile
├── requirements.txt
└── README.md
```

## 1. Add your trained model

This app expects **one file**: a scikit-learn `Pipeline` that includes both
preprocessing (encoding, scaling) and the trained classifier, saved with joblib.

If your Colab notebook currently trains and encodes separately, wrap it into a
single Pipeline before saving, e.g.:

```python
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler
import joblib

categorical_cols = ["gender", "Partner", "Dependents", "PhoneService", ...]
numeric_cols = ["tenure", "MonthlyCharges", "TotalCharges"]

preprocessor = ColumnTransformer([
    ("cat", OneHotEncoder(handle_unknown="ignore"), categorical_cols),
    ("num", StandardScaler(), numeric_cols),
])

pipeline = Pipeline([
    ("preprocessor", preprocessor),
    ("classifier", your_trained_model),  # e.g. XGBClassifier, RandomForestClassifier
])

pipeline.fit(X_train, y_train)
joblib.dump(pipeline, "churn_model.joblib")
```

Download `churn_model.joblib` from Colab and place it in `model/churn_model.joblib`.

> Why a single Pipeline? At inference time the API receives raw fields (e.g.
> `"Contract": "Month-to-month"`), not pre-encoded numbers. If encoding lives
> inside the Pipeline, `model.predict()` handles it automatically — no need to
> duplicate your encoding logic inside the API.

## 2. Run locally

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Visit `http://localhost:8000` for the form UI, or `http://localhost:8000/docs`
for interactive API docs (Swagger UI, auto-generated by FastAPI).

## 3. Run with Docker

```bash
docker build -t churn-app .
docker run -p 8000:8000 churn-app
```

## 4. API

**POST** `/predict`

Request body: customer fields matching `app/schema.py`. See `/docs` for the
full schema and an example payload.

Response:
```json
{
  "churn_prediction": "Yes",
  "churn_probability": 0.7823
}
```

**GET** `/health` — returns `{"status": "ok"}`, used for container health checks.
